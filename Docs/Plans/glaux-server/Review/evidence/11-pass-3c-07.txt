### 2. Security review — IDR-038 against Guide §§4.9/4.10 and the owning leaves

Method: each IDR-038 recommendation was classified as either a safeguard the Goal/Guide/standards actually require, or a mechanism the research proposed to realise it. Only the former can be "missing".

**Required safeguards — present in the Guide and leaves (no finding):**
- Accountability committed with the decision: `glaux-server-implementation-guide.md:501` ("commits resource state… audit information… in one transaction") and `glaux-server-implementation-guide.md:600` ("committed write/command accountability cannot depend on [diagnostic logs]"). This is fail-closed by construction — IDR-038 §11.5's fail-closed rule is satisfied without a separate audit service.
- Recheck immediately before dispatch and exactly one dispatch under concurrency: `glaux-server-implementation-guide.md:580`; Roadmap 5.2.4/#165 Done text ("Concurrent workers produce one admitted dispatch; revoked authority, changed contracts and elapsed execution deadlines cannot bypass checks"). IDR-038's single-use ticket/fence (§9.4) is one way to implement this, not a requirement.
- Deny by default; no allow on policy-service failure: `glaux-server-implementation-guide.md:596`; #22 acceptance text.
- Protected discovery of command capabilities/schemas: `glaux-server-implementation-guide.md:598`.
- Submission permission separate from status/result reporting authority; submitter cannot impersonate `sender`: `glaux-server-implementation-guide.md:574`, L596.
- Fail-safe when token verification is unavailable (cached issuer keys, bounded refresh): L594.

**Optional research mechanisms — not adopted, and not missing requirements:** `CommandAuthorityGrant` and `ControlAuthorityLease` with exclusive/coordinated modes (IDR-038 §§6.1, 6.3; upstream #58 remains open, and the Guide places interlocks with device adapters at L580); approval/override decision records (§6.4); the dispatch-ticket encoding (§9.4); signed DDIL authorization bundles and command operating classes (§13); emergency stop modelled as its own command (§8.4). Guide §12.2 declines a "universal policy or trust engine" deliberately.

**Effect on existing findings:** F-03 is unchanged (Low–Medium). IDR-038 §6.1 shows research had an action vocabulary; the residual gap remains that the Guide does not name the minimal actions/scope units the #22 matrix must cover, so the matrix rows become de facto policy. Approval/override/lease actions are optional and outside F-03.

**Carried to Pass 4 (scenario, not a finding):** a disconnected node whose cached issuer keys expire denies all tasking (fail-safe); whether that consequence is documented for DDIL deployments needs Guide §4.11 and its owning issues read first.
