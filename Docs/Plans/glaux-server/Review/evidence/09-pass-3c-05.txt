### 3. New finding

**F-18 — ControlStream `live`/`async` ownership and non-live admission are unspecified.** Severity **Low**; type: missing rule (unresolved question). Rule followed: complete reads of Guide §§4.6, 4.9, 6.4 and the owning issues #156 (stream registration/metadata), #163 (admission), #164 (POST surface).
- **Evidence.** The Guide never mentions `live`; the word `async` appears only as prose ("synchronous/asynchronous"). #156 delivers "generated stream metadata" without naming these fields; #163 rejects "invalid parameters, forged sender, denied targets"; #164 covers `201`/`Location`/`Content-Location`/`PENDING` and concealment. None says who sets `live`/`async` (client-supplied vs server-derived; register #65 records the same ambiguity for DataStream `live`) or what a command/feasibility POST returns when `live=false`. Research does: IDR-037 §6.3 ("reject … before creation with stable `409 Conflict`… A gateway becoming unreachable after asynchronous creation does not retroactively turn creation into an HTTP failure"); IDR-036 §6.1 (`live` means the stream can accept live Commands; not reachability) and §6.3 (internal `active`/`suspended`/`retired` states).
- **Failure scenario.** An implementer either accepts commands into a stream advertised `live=false` (misleading clients that check it) or invents a status (`403`/`503`) that differs from research and peers; the independent runner has no expected answer for the fixture.
- **Mitigation checked.** Guide L944 fixtures include synchronous/asynchronous ControlStreams but not a non-live one; #163's "denied targets" is an authorization case, not stream state.
- **Smallest correction.** One sentence in §4.9: `live`/`async` are server-managed stream metadata (or client-supplied and validated — owner's choice), and a POST to a stream with `live=false` returns `409` before any resource or work exists (IDR-037 §6.3). Add the case to #163's Done text. **Test:** `live=false` fixture → `409`, zero Command/status/work rows; `live=true` → `201`. **Timing:** before #163.
