### 2. Security review — IDR-040/041 against Guide §4.10 (required vs optional)

All statements below concern design text and leaf acceptance criteria, not executed verification.

**Required safeguards — present as design text (no finding):**
- Authorized view built before data access, so counts, extents, links, latest selection, schema disclosure and streaming reveal only the caller's view: `glaux-server-implementation-guide.md:596` — matches IDR-040 §8.1/§8.4 ("never substitutes global totals"; "latest means newest releasable record in the authorized view"). Also consistent with IDR-011 §10.1 (authorization before predicates) already verified.
- Schema-true disclosure: a protected field is not simply removed if that falsifies the advertised schema; define a valid projection/profile or deny the representation: `glaux-server-implementation-guide.md:598` — matches IDR-040 §1/§8.3 ("must not emit a dead link as camouflage").
- Links, schemas, command capabilities, original artifacts, error details and replay history protected like data: L598 — matches IDR-040 §§6.1, 8.3.
- No labeling regime hardcoded; IC-EDH/ISM or STANAG 4774/4778 integration requires an authoritative policy and concrete binding profile; no adapter selected: `glaux-server-implementation-guide.md:610` — matches IDR-040 §1 ("no single national, NATO… regime is hardcoded").
- Audit committed with the mutation; denials recorded safely without unbounded load; no secrets/tokens/raw payloads/protected reasons logged; accountability independent of sampled diagnostics: L600 and §4.6 L501 — matches IDR-041's minimum slice (atomic journal append; independent failure spool). Guide L600's "a mandatory tamper-proof ledger… is not proposed" is consistent with IDR-041 itself, which rejects "tamper-proof"/"non-repudiation" claims (L74, L455, L737).

**Optional research mechanisms — not adopted, not missing requirements:** the three-record `PolicyAssertion`/`PolicyBinding`/`DisclosureDecision` model and `ALLOW/DENY/INDETERMINATE` + `REVEAL/CONCEAL` envelope; the transform catalog beyond pass/project/deny (generalize, aggregate, delay, suppress, minimum-cohort aggregates); an explicit "Glaux is not a cross-domain solution or release authority" statement (true, and implied by L610, but a clarification rather than a requirement); hash-chain/checkpoint/MAC/WORM integrity layers (IDR-041 §§11–13, conditional even in the research).

**Effect on findings:** none new. F-03 unchanged — IDR-040 §5.2's explicit combining rules ("no unmarked-means-public, local-means-trusted, lexicographic order, last-writer-wins, or client-selected downgrade") are the kind of stated defaults §4.10 leaves to the #22 matrix; still Low–Medium.

**Standing qualifications carried:** documented safeguards ≠ executed verification (Pass 5); one admitted dispatch ≠ exactly-once physical effect (Guide §6.4 disclaims; IDR-029 §11.2); offline authentication follows the #21/§4.10 bounded key-cache policy (fail-closed on expired trust); F-18's three qualifications.
